# 声音设计与混音

写入或下载文件前，先落实[保存位置与临时文件](references/storage.md)：复用已有配置；缺少时只向用户确认存放习惯及素材、项目的位置。输出与缓存落点明确后再执行，独立任务不强制建整片项目。

先确定声音怎样推动表达，再选源、编辑和混音，最后在画面与对白上下文中听结果。独立试听或单个接点可直接处理。

## 恢复实际声音

确认版本、原生 VO/同期声、音乐、SFX 的用途、源区间与时间映射。用户已有粗剪时保留真实原轨、剪点、变速与人工电平；不得从不完整端点重拼 VO 或引用旧版干声。

先核实真实听音路径。能给用户播放、ASR、音效分类和响度都不等于 Agent 已听到。复用有效观察；能力失败时明确待听范围，继续可做的设计/预览，不能虚构自然度。

反复选源/制作试听且已获委派授权时，可用不继承历史的内部任务；输入完整相关原要求、当前音轨基准、有限候选、时钟和足够两侧声画。只在指定候选目录试做，返回源窗/混音文件、实际听审范围与未查项；负责人核对原要求并听查合入后的受影响上下文，不能以子任务完成替代整片核查。单个已限定 API 调用直接执行，不重复传历史 WAV 或整片快照。

## 设计与实现

1. 明确听觉主角、层次进入/退出、情绪延续或转折，及声音与画面的分别切点。音乐、转场或声画组合有问题时读[音乐衔接与声音设计](references/sound-design.md)相关部分。
2. 使用已有候选或实际可调用的声音库/API，按声音角色找源窗口。比较真实音色、节奏、密度、起音和尾音；保留来源、区间和采用理由。工具未接入不证明库里没有素材。
3. 先解决乐句、器乐/鼓层、入口、过门与尾奏，再混电平。BPM/onset 仅作线索，短淡化或 SFX 不能替代编排。关键声音在现有记录/标记中保留目的、进入/落点/尾音。
4. 用受保护的同一基准实现失败接点及足够两侧上下文。候选按需要提供，差别应在声音方案上，不只是音量；用户要求多版本时保留可比较候选。使用受支持的 CLI/API/MCP 或明确离线处理，保留可编辑分轨。
5. 检查必要的 solo、VO+音乐和带画面全混音：过门是否能感知、落点/音色是否连贯、对白清楚、音乐维持作用、动作声同步、禁用现场声已移除。LUFS、非零波形和长度只验证相应技术事实。代表段成立后再扩展请求范围。

接口不支持高级音频功能时说明具体缺口，不自动接管前台。源声修整/降噪检查实际延迟、字头尾、音色与底噪衔接，不能为降噪破坏口播。

## 合入与返回

- 合入整片核对实际输入、源时钟和角色范围，与当前原生参考比较；不能用补零长度伪装音乐覆盖。按影响检查回接两侧、正文、循环与尾部。
- 源声处理、分轨、全混音和最终导出分别核对内容、同步与电平；全混音检测不证明原 VO 被保留。其他轨道/调色不能因换音被回退。
- 替换或离线处理声音时核对源声道、剪辑增益、轨道/总线路由和处理延迟；源文件音量不等于原生已处理音量。保留参考对白与相邻 BGM 的相对电平，不能漏掉原有前级增益。
- “双声道”需要检查实际有对白窗口的逐声道能量和播放，必要时比较 VO solo 与全混音；channels=2 只说明容器/流布局，音乐两侧有能量也不能证明 VO 居中。居中单声道人声可按需要送入左右两侧，立体声音乐无需强行双侧波形相等。技术测量失败/为空应记未查，不当作通过。
- VO 内容/采用变更要同时处理声画整体；长度或切点变化核对字幕、包装与反馈映射。已被否定的效果仍未通过，需要对应设计变化和实际核查。
- 回到同片版本与原反馈，说明采用理由、试听范围和剩余项；片段试做不自动替代整片交付。用户接受独立记录。

当前项目采用本套 Workflow/Epidemic/Pipeline 接入时，读[工具接入](references/workflow-adapter.md)。其他声音库和编辑工具按实际公开能力使用，无需采用本机目录格式。
