# Workbench / Pipeline 接入

仅在当前项目已使用本套 Workflow/Pipeline 时读取。本页说明该工具组合的命令与数据约定；其他环境使用自己的公开接口，无需仿造这些文件。

先确认 `video-workflow` 可用及本机绑定；`video-workflow resource ID --read` 解析下文资源，`video-workflow run PROVIDER:COMMAND -- 参数` 调用工具。缺绑定时说明具体能力缺口，不能猜相邻目录或自动初始化项目。需要发现才用 route/brief，已知入口可直接调用。原生执行约定为 `workflow:resolve-execution`：核对实际支持、工程/时间线与单写入者，失败不自动回退前台。

- 查 `workflow:media-evidence-method`，先读 screening-brief、有效事实、coverage、关系、转写、排除及 visual-index/presentations；库/缓存保存产物，项目保留引用。
- take-inspect 返回上下文、重启/重复/边界线索和 observation_reuse；available 不等于观察合格。外部观察经 fact-record 用真实 actor、源范围与 prepared 引用写回，不冒充 human 或关闭未看 coverage。
- 导出 selection_package 保留事实、源时钟、决定、take 检查及 partial/unknown；完成范围按 `workflow:screening-stage-acceptance`。需要更广的方法来源可读 `workflow:editorial-grammar`。
- 已有剪辑用 Pipeline 的 `source-link-screening` 补接指定源筛选快照，报告路径不能代替绑定。带用户 DRT 时先离线读引用，确需恢复见 `pipeline:native-intake`，由原生写入者执行。
