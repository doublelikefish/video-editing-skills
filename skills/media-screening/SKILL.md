# 素材观察与候选

写入或下载文件前，先落实[保存位置与临时文件](references/storage.md)：复用已有配置；缺少时只向用户确认存放习惯及素材、项目的位置。输出与缓存落点明确后再执行，独立任务不强制建整片项目。

确定这次是接收/增量、独立整理，还是为某个表达查找镜头。使用现有素材目录、观察、转写与缓存；独立查找可以直接返回候选窗口。

## 先复用，再补看

- 原片、卡结构和侧车保留。先查已存素材索引、表达对应、有效观察及排除理由；目录无命中或一次搜索为空不证明素材不存在。
- 包含相关已用、未用和未进入计划的候选；计划列表不代表全库覆盖。局部请求不默认重扫全库；用户以镜头举例说明普遍遗漏时，按完整要求恢复适用段落和相关候选池。
- 仅为缺失、歧义或变化的范围补观察。区分来源事实、模型判断和人工决定，记录真实观察者及检查范围；局部采样不能称整源已看。
- 图片/音视频按当前问题分批输入，完整素材和观察留在文件；已查内容后续优先引用源身份、窗口与结论。不要打印含 base64 的工具结果或重复加载整套图册。缩略图用于概览，动作/细节核查仍需合适的实际媒体，只有路径不算已看。
- 一组候选需要多轮观察且已获委派授权时，可使用无历史继承的内部任务，传完整相关原要求、采用基准、候选/源窗和已有观察；任务只补事实，不改采用。回传候选窗口、证据路径、排除理由和未查范围，负责人按原要求与实际媒体比较。单次有限 API 分析直接运行即可，不为每张图另开会话。

## 给出能剪的窗口

- 按任务观察主体/状态、动作阶段、运动方向与速度、焦点、可用落点/余量和源声音。需要运动或短动作判断时读[动作与运动观察](references/shot-observation.md)；标签和物件出现不是采用理由。
- 稀疏静帧不足以确认完整运动或排除短动作；ASR、波形和响度不证明实际听感。补连续片段时先核实真实源与流，复用可用缓存。
- 返回源身份、流、原速区间、实际证据、用途与不确定性。区分源时码、时间线时间与代理时间，不用近似模型时间直接作帧精度剪点。
- 具体瑕疵只约束实际有问题的窗口；不将一处色彩或构图问题扩成整组禁用。查看 ROI 不自动成为成片裁切；机型或目录不能确定输入色彩。

## 交接

给出相关候选、可用区间、排除依据和未查范围；正式录次/最佳表现由剪辑时比较。备份核验与内容筛选分别说明，不因已入库宣称已看完。

已有工程只补接观察引用，保留采用和剪点。若本轮是已有 Review 链的反馈修改，把候选比较和排除证据回到原反馈/批次，不能只留在聊天或本片临时文件。涉及原生导入时交当前写入者通过受支持 CLI/API/MCP 完成；不能用重新装配代替恢复用户粗剪。

当前项目已接入 Workflow/Workbench/Pipeline 时，读取[工具接入](references/workflow-adapter.md)，使用其查询、事实写回与交换格式；其他工具沿自己的公开接口保存同等事实。
