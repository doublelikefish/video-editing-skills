# 视频剪辑

用户说“剪视频”“继续这条片”“按反馈修改”等制作请求时使用。安装后由 Agent 读取本 Skill、补齐必要信息并执行；用户无需另学命令、手工建规范文件或安装整套 Pipeline。仅讨论方法或开发软件时不启动制作。

本文件简化自既有 **一个总控 + 九个阶段 Skill**：保留各阶段的输入、判断、工具调用、交接和验收，去掉专属仓库、固定盘名、服务和登记格式的前置依赖。它自身能指导完整流程；已安装详细阶段 Skill 时，按本轮需要读取，不要求全部安装。

## 先看全程：10 个环节，按已有成果进入

| 环节 | 原有职责 / 可选详细 Skill | 本环节交给下一环节的东西 |
| --- | --- | --- |
| 1. 项目配置与接续 | 本 Skill `video-production`（沿用原总控职责） | 已落盘的配置、当前基准、有效要求和可用能力 |
| 2. 创意、文稿与分镜 | `video-preproduction` | 表达主线、段落职责、参考用途和待拍/待制内容 |
| 3. 素材接收与筛选 | `media-screening` | 源文件、候选窗口、观察依据和未查范围 |
| 4. 初剪与精剪 | `video-first-cut` | 有明确源区间的剪辑、连续声画和可反馈预览 |
| 5. 输入还原与调色 | `video-color` | 正确输入解释、机位匹配、保留的风格与对照 |
| 6. 包装与画面组合 | `video-motion` | 已应用的模板/图形/分屏及可编辑源 |
| 7. 声音设计与混音 | `video-sound` | 明确的 VO/同期/BGM/SFX 关系和真实听审结果 |
| 8. 字幕 | `video-subtitles` | 对应实际台词与当前剪辑的文字、时码和显示 |
| 9. 审片、反馈与修改 | `video-review` | 每条要求对应的修改、核查和待复核版本 |
| 10. 输出、交付与归档 | `video-delivery` | 正确交付版、工程/依赖、检查结果及接续位置 |

这是职责地图，不是十次审批或必须串行的十道工序。新片通常 1 → 2/3 → 4（交叉处理 5–8）→ 9 → 10；已有粗剪从 1 → 4；反馈从 1 → 9 → 相关环节 → 9；增量素材从 1 → 3 → 受影响环节。缺镜头回 3，表达改变回 2。单次裁切、转码、修声音直接进对应环节，只落实输入、输出、临时位置与核查，不创建整片框架。

**初剪就要有可理解的声音、必要的基础色彩、用户要求的机位与包装布局。** 5–8 单列方便按需精修，不能借此把它们都推到用户审片后。对白 cue 在配画面前介入，正式字幕样式可以后做。

## 1. 项目配置与接续：先落盘，再执行

**获取 / 交互**：先读用户已给的信息和当前项目记录，只补问缺项。没有制作目标时先问这次要剪什么、有哪些输入；缺存放配置时问“有没有惯用的存放方式？素材在哪里，项目存哪里？”同时确认使用的软件、交付用途/比例/时长、已有粗剪与必须保留内容。已知信息不重问，普通工具选择由 Agent 决定。

**执行**：区分用户设备与 Agent/工具执行端，检查可访问的路径、编辑器版本、读写接口与看听能力。安装软件不等于可控制软件，能读文件不等于能改工程。已有项目先恢复真实当前采用，不按最大版本或最近文件名推断。位置充分且有写入能力后，立即按下方模板在项目根创建/补充入口文件，读回验证并继续本轮工作；不能只建议用户创建，也不能写完文件就结束剪辑任务。

**文件动作**：新项目默认创建 `AGENTS.md` 与仅作导入的 `CLAUDE.md`；项目现有规则逐段保留，只补缺项。当前宿主已有适用入口时沿用并指向共享规则；其他宿主查其加载方式。没有项目记录时创建 `PROJECT.md`；已有记录就引用，禁止另维护一份“最新”。不得覆盖已有用户规则或改全局设置。无法写用户电脑时说明限制，交付可保存的文件内容和位置，不能说已创建。

**保存与命名**：沿用用户目录/命名习惯；没有时建议项目内 `work/` 放工程、制作脚本和采用资产，`output/` 放版本预览/交付，`temp/` 放可重建临时文件，用到才建目录。原片原位只读；新输出采用 `<项目名>_v001_<用途>.<扩展名>`，不覆盖旧版、不改相机原名。读回目标磁盘和可用空间；输出、下载、抽帧和工具临时目录明确传入，离线或不足不能静默改写系统盘、会话或素材盘。数据库实际位置单独记录，不搬活动库。

**得到什么 / 接下去**：项目入口可读，原片与工作位置分开，基准、要求和能力缺口明确。已有文稿/粗剪就跳过重复筹备；只缺某项能力时继续独立可做部分，记录待输入。

## 2. 创意、文稿与分镜

**获取 / 交互**：读取目标、观众、文稿/参考和已有内容。仅在主线、风格或重构范围不明确时给用户简短选项；已有采用不要求重选。

**执行 / 能力**：明确每段让观众知道、看到、感受到什么；把文稿、参考、拟用画面和真实拍摄候选对应起来。拍摄顺序不等于叙事顺序，用户已剪结构则是基准。文字梳理由 Agent 做；只有需要查参考才检索，需要分镜图/生成素材才调用相应已连接能力，普通结构讨论不调用生成 API。

**产出 / 进入下一步**：保存简短表达/分镜计划，含段落、内容职责、参考用途、现成输入和缺口；估算时长不作真实 VO 时码。已有素材去 3，缺实拍则明确拍摄内容；已有结构直接用于 4，不强制做 Layout/分镜产品。

## 3. 素材接收与筛选

**获取 / 交互**：读取素材目录、已有索引/图册/转写、用户指定镜头及用途。缺文件先核对已给路径和相关候选，不因搜索一次没命中就要求补拍。

**执行 / 能力**：先读已有证据，再用元数据工具核实源身份、帧率、音轨、色彩依据和同步。按需要抽帧/做图册/转写/分析连续片段；观察主体、动作阶段、运动方向与速度、焦点、稳定性、可用头尾和源声音。相关未采用和未进入计划的镜头也比较，单个瑕疵不等于整组禁用。静帧不能证明完整动作，ASR 不能证明语气与听感；对白驱动内容在配画前形成对齐真实声音的 cue。

**产出 / 进入下一步**：候选带 `源身份 + 源时间区间 + 实际观察范围 + 可承担职责 + 问题/未查项`。候选不等于采用，交 4 比较选条；需要改变表达才回 2。复用缓存，仅补缺失/变化观察；媒体留文件，按问题分批看，不把 base64 或全部图册反复塞进对话。

## 4. 初剪与精剪

**获取 / 交互**：读取原生粗剪/当前采用、实际台词、候选、人工修改和本轮必须呈现的内容。仅在要改变已采用结构或重要创意取舍时对齐；明确的局部修改直接做。

**执行 / 能力**：先保存可恢复副本并核实活动工程、时间线和完整音画基准；按受支持 API/MCP/CLI 执行。同一应用实例只允许一个写入者，切工程也算写入。没有原生接口不能从不完整端点重建“等价”粗剪；所需可编辑工程不能用整片 MP4 塞入轨道冒充。

先选完整句群/表演，再处理重复、失败重启、气口、动作起落与节奏。每个 B-roll 明确解释/证据/情绪/遮切口职责，确定源窗口、进入点、退出点和退出后主画面；连续检查前后句群及全部相关图层，避免口播回闪、覆盖错句。直切、动接动、静接静、裁切缩放、分屏、画中画、J/L-cut 按表达使用，不能只列技法名。整体或分段提速保持对应的画音、字幕、包装映射和用户节奏。

**产出 / 进入下一步**：真实可播放的初剪或局部修改，保留源/时间映射及关键采用理由。把必要的 5–8 合入本版；新复杂效果先验证有上下文的代表段再扩展。缺输入用明确占位说明范围，不能称完整初剪；本轮要求核查后去 9。

## 5. 输入还原与调色

**获取 / 交互**：读取真实源信息、项目色彩管理、现有手调/LUT、已认可参考；仅在缺风格选择或源信息影响转换时向用户询问。

**执行 / 能力**：先确认转换归属，避免漏转/双转；输入不明保留 unknown，不按机型猜 Log。先曝光、白平衡、肤色和机位匹配，再处理风格。通过支持的调色接口落实，不把“有参数”当实际生效。

**产出 / 进入下一步**：相同源/时间的前后对照、应用对象和未查项；看变化段与相邻机位。其他环节替换素材/重导出后再核对现有调色没有丢失，回 4/9。

## 6. 包装与画面组合

**获取 / 交互**：定位本片已采用模板、文字/品牌、参考、源窗口和画面职责。没有指定样式且影响观感时用代表画面/短段对齐；已有模板不重新发明。

**执行 / 能力**：决定单画面/分屏/画中画/标注的内容主次、进入、可读停留和退出。复用正确模板版本，按本片替换内容，不能直接闪插旧模板示意图。按能力选原生合成、现有模板渲染器或生成工具；有现成资产就不再生成。关键效果在现有记录/时间线标记留目的、源和落点，不为每个效果强塞 SFX。

**产出 / 进入下一步**：可编辑源、实际回填对象及合成预览；核查安全区、文字、遮挡、透明度、动态首尾和声音关系。渲染成功不代表时间线已合成正确，检查后回 4/9。

## 7. 声音设计与混音

**获取 / 交互**：恢复实际 VO、同期、环境、BGM、SFX 与原有处理。已有选定音乐先用；需要新情绪方向时给真正不同的可听候选，用户要求多版就保留比较版本。

**执行 / 能力**：先确定每层职责与声画衔接，再选源、编排、混电平。音乐换段比较乐句、器乐/鼓层、密度、音色、入口和尾奏；按意图选 J/L-cut、节奏过门、器乐/SFX 桥接或有意留白。淡入淡出、短 whoosh 不能代替音乐编排。需要新声音才搜索已接入的声音库/API，比较真实源窗口，记录来源及采用理由；普通电平修复不用重新搜库。

清理不需要的相机声/持续噪声，保持人声自然；按内容做 ducking 和动态，而非套固定数值。检查有效对白的实际声道与路由：容器为双声道不证明 VO 两边都在。保留立体声音乐，不能无理由全片双单声道。

**产出 / 进入下一步**：声音源/窗口、进入落点尾音及分轨/混音；先单独听问题层，再带画面和前后上下文听，检查 VO 清晰、BGM 连续性、SFX 相对响度、接点与尾部。没有音频检查能力写未听审，不能选“最佳”，回 4/9。

## 8. 字幕

**获取 / 交互**：使用实际采用对白、已校对转写、字幕模板与输出要求。只对听不清/术语不明的关键字询问，不让用户重交已提供文稿。

**执行 / 能力**：无转写且有对白时才调用 ASR，再结合声音校准；无对白或不需要字幕就跳过。源时钟、切点、速度与时间线共用映射，保留人工校准。用字幕工具/编辑器生成或修改轨道/SRT等，不覆盖已有手调轨道。

**产出 / 进入下一步**：文字、时码和实际显示；检查字头尾、跨切口、换行、阅读时间、字体、安全区和包装遮挡。字幕轨、烧录设置、导出可见字幕分别核实，回 4/9。

## 9. 审片、反馈与修改

**获取 / 交互**：读取聊天、文档或 Review 的全部有效要求，排除删除/明确取代项，保留原意见 ID/原话、版本和位置。用户自然表达，由 Agent 整理；只问无法定位或互相冲突的部分。用户举例指出普遍问题时恢复完整适用范围，不能只改示例。

**执行 / 能力**：先从原要求拆出每个核查条件，再做修改，不从“我做了什么”倒推通过。每条按 `原版本/位置 → 要求 → 本轮决定 → 实际结果版本/位置 → 技术核查 + 真实看听 → 剩余` 更新，复合要求分别处理。回相关环节执行，在改后输出检查本处、前后衔接及受影响的声音/色彩/字幕/包装；复用未变化的有效证据。

Review 产品可选：新项目可直接用聊天/文档；已有 Review 链或用户要求 Review 时必须完成版本登记/绑定、页面媒体与定位核对，再交链接，并回到原意见。登记是独立交付动作，导出不等于登记。服务不可用说明缺口，沿已授权备用方式继续可做部分，不能悄悄丢链。

**产出 / 进入下一步**：逐条回传 `已修改待用户复核 / 部分完成 / 待输入 / 待定位 / 无需修改（依据）`。“已修改待用户复核”要求本轮内部核查已完成；需要的实际看听还未做时，写“部分完成：技术已核查，视听待查”，下一步保留 Agent 的检查动作，不能把内部漏查转交用户验收。漏做或未查一项就不标整条通过；用户接受单独记录。反馈未完继续相关环节；满足本轮交付条件去 10，后续意见仍回本环节。

## 10. 输出、交付与归档

**获取 / 交互**：确定具体输出版本、工程/成片范围、平台规格、字幕方式与交付位置。用户已授权导出就执行，发布另按已有明确授权处理，不把每次输出变成确认关卡。

**执行 / 能力**：从正确工程/时间线保存快照，设置并读回范围、尺寸、帧率、编码、色彩、音轨/字幕，再渲染本次作业。检查真实文件而非仅检查返回码；整片交付连续审片，局部交付检查变化与上下文，明确未查范围。整片未完成可给工作预览，不能报交付已通过。

**产出 / 结束**：交付可访问成片、按要求的可编辑工程、必要资产/依赖及逐条结果，更新当前采用/待办引用。工程备份不等于已包含原片。只清理本次创建、无使用中任务且无成果依赖的可重建临时文件；保留采用资产和回执，历史清理另处理。文件完成、内容核查、用户接受分别说明，不自动发布或代填接受。

## 工具如何选、如何调用

每次涉及新能力按下面流程；已验证且未变的配置直接复用：

1. **由环节需要找能力**：文件/元数据、真实媒体观察、转写、时间线编辑、声音、色彩、渲染、反馈。先查当前工具列表、已安装 Skill、软件公开接口和已有项目接入，避免重新造工具。
2. **核实支持范围**：分别确认用户系统与执行端、软件版本、操作系统支持、输入输出格式、认证与费用；系统和软件不能一对一绑定。只读探测具体能力，不能为测试擅自切活动工程。
3. **先用现成执行入口**：CLI/SDK/API、可用 MCP/插件优先；先看当前 help/schema，再传明确输入、源/时间范围、输出与临时位置。已接入 Workflow/Pipeline 的项目沿其 route/brief 与原阶段适配说明恢复；其他项目不要求这些命令。
4. **缺能力时补最少一项**：查官方说明或可核实的工具，按用户系统/编辑器推荐。仅安装本轮确需且已授权的依赖，使用该工具的依赖清单/安装方式并验证；本 Skill 无统一媒体 requirements。现成接口不足可写本片最小脚本，做完再判断复用，不在剪辑中另建框架。
5. **失败与替代**：接口失败先定位原因，不能自动抢前台、换软件或重建时间线。有可靠 GUI 路径时说明需要占用界面并沿授权操作；不能访问用户软件时提供可导入成果/明确步骤，标明哪些操作仍未完成。用户要求自动成片时，指南不算交片。
6. **调用后读回**：绑定真实输出/工程身份，核实参数和内容。外部生成只返回文件引用、必要参数与短结论；完整 payload 留本地，不打印 base64。路径引用本身不等于已经看听。

使用 Resolve 建初剪时，按 `video-first-cut` 的“使用 Resolve 创建或接续”处理启动、等待和空白工程；没有挂载 MCP 就用已有 Python SDK，不能把一次连接失败直接变成用户手工操作或降级交付。

## 项目文件模板：由 Agent 填写并实际写入

新完整项目用下面两份内容加一个 Claude 导入文件即可。把占位符替换为本片事实，非关键未知写“待确认/未验证”；项目根和本次写入位置未知时先问，不猜。已有项目合并缺项、保留原规则；已有状态记录时省略 `PROJECT.md`，把入口中的名称换成真实记录引用。

### AGENTS.md：项目规范与接续入口

```md
# <项目名称> · 视频制作约定

## 目标与配置
- 本片目标/受众/交付规格：<事实>
- 用户软件与版本：<事实>；Agent 执行端：<事实>
```
