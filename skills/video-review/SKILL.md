# 反馈到制作结果

写入或下载文件前，先落实[保存位置与临时文件](references/storage.md)：复用已有配置；缺少时只向用户确认存放习惯及素材、项目的位置。输出与缓存落点明确后再执行，独立任务不强制建整片项目。

回收有效要求，交给负责内容的阶段制作，并把实际结果关联回原意见。聊天、文档和评审工具都是正常反馈载体；Review 产品是可选能力。用户自然表达，由 Agent 按[反馈与回传格式](references/feedback-format.md)整理，已有信息不要求用户重新填表。

## 先确定反馈载体

Review 的可选性按项目判断。开始本轮前检查当前项目接续、历史版本、有效反馈批次和 Review 登记。只要本项目已有 Review 链、`review_feedback` 绑定、Review 根目录/登记文件、上一版 Review 回执，或用户已经在 Review 中提出意见，**默认继续使用这条 Review 链**。新 v01、v02、v03 等预览沿同一媒体/版本父子关系登记，意见和结果用原 ID 回写。当前版本尚未登记，不代表可以静默改成聊天直链。

没有历史 Review、没有项目绑定、用户没有要求 Review 的新项目，可以直接使用聊天或文档格式。用户明确要求直接聊天时，才切换载体。Review 服务暂时不可用时，可以在用户知道并接受的情况下临时用聊天回传，同时记录切换原因、原 Review 链和待同步范围；不能把直链说成已经完成 Review 回调。

“导出审阅版”只说明要生成可观看文件；“用 Review 工具审片”“打开 Review”“沿现有 Review 修改”说明要登记版本并返回 Review 页面。当前项目已有 Review 链时，未明确说放弃它，按 Review 链处理。

## Review 产品的专门环节

选用 Review 后按这个顺序工作：

1. **评审登记**：登记或复用媒体对象和版本，绑定父版本、实际预览文件、帧率/起点、采用计划和可定位的时间范围。
2. **登记核对**：读回登记的版本、预览身份、时钟和可访问入口，确认页面反馈会落到这条版本链。
3. **评审反馈**：用户在登记版本上观看、定位和留言，Agent 读取当前有效意见。
4. **制作回传**：修改完成并实际核查后，把结果版本、证据和原意见关联回去，状态保持待复核或部分完成。

没有完成第 1 步时，文件只是导出预览，不能称为 Review 版本，也不能用 Review 页面时码当作已登记反馈。登记本身不代表用户看过、作品通过或用户接受。

## 恢复有效范围

- 确认用户实际观看的媒体/版本与反馈锚点，读取意见正文、附件及后续讨论。排除已删除、测试和被明确取代的意见，不能只看最新几条。
- 一起恢复待制作、历史待映射、部分完成和已返回待复核。版本变化先核对源与时间映射；未知位置保留未映射，不凭近似时码伪造精度。
- 用户以一个案例说明普遍问题时，恢复完整有效要求、适用段落、相关候选池、实际采用和效果；单点要求也不自动扩成全片返工。重复提及同素材不证明成片重复。

## 决定与制作

写清本轮预期效果、修改对象、保留内容与完成依据；编辑推断不能写成用户要求。修改前重新核实意见修订，避免依过期要求执行。

同一条意见内的多个动作分别保留完成条件。例如“稳定、旋转、放大”有三项，完成裁切不等于完成稳定。指定镜头还要核对源窗口、动作与顺序。多条/复合反馈或反复退回时读[修改后逐项核查](references/revision-verification.md)，把条件留在原反馈的决定/检查中，不另建任务库。

按问题调用可用的筛选/剪辑/声音/色彩/包装/字幕 Skill，或直接用相应职责完成。反复退回先在真实上下文验证修法，保护当前结构、VO、用户手改与共同时间映射。原生操作通过受支持 CLI/API/MCP 并保持单写入者。

## 核查与回调

- 多轮媒体复核可在有授权时交给不继承历史的内部任务。给它有效原话/附件、当前采用与待验结果、保留项和证据定位，不能仅给执行者总结；核查只读。结果保留逐项实际检查、失败与未查，负责人对照原要求接回并通过原载体回写。任务状态完成不改变意见状态，小批明确反馈不必另开任务。
- 核对实际结果和受影响上下文，分别记录技术读回、真实视听、未查范围；换镜、改参数或工具成功不直接等于效果满足。
- 核查时重新从有效原话/附件列出应满足项，逐项对照结果，不能只照执行者的“已完成”摘要验收。遗漏条件、错误源窗、检查失败或效果未查均保留在原条目；只核对意见数量不能证明改全。
- 对修改点检查连带保留项：换镜后的色彩解释、裁切/稳定、源声路由与增益，嵌套内外层合成，以及前后切口。证据必须对应最终实际预览；之后再改相关输入、参数或合成时重查受影响项。
- 已有意见的复查追加到原意见的证据/讨论，注明对象、源/时间、证据及限制；真正新问题才创建新反馈。未登记候选明确为候选，不冒充已登记版本。
- 沿选定载体关联原意见、结果版本、实施与检查：聊天直接回复对应反馈，文档更新原条目，已使用的评审工具通过公开接口回写。没有选用工具时不登记、不等待同步；只有用户/项目已要求同步到服务而尚未完成时才记录该缺口。通知其他制作方须有授权，通知不替代实际结果回传。
- 完整实施后是已返回待复核；部分实施保留剩余工作、pending/failed 检查和进行中状态。未听/未看内容不能从验收范围删除。
- 已返回待复核仍需在后续影响到它时回归。回调后读回原意见、结果版本及各项检查，核对有效 ID 集合与未完成项；数据库状态、登记成功和网页能播放都不替代内容验收。
- 用户接受由明确确认或已约定的接受规则决定，且限实际观看与完成范围；不由程序代填。无新输入不重复派同一失败任务或追加等待记录。

## 交付

区分整片修订、关联片段/备选与独立媒体。聊天交付可访问文件/预览、明确版本和逐条处理结果，用户可继续在本对话反馈；使用评审服务时另核对登记、页面和意见定位。映射缺口明确说明，局部试做不关闭整片任务。

沿用当前选定载体作为反馈主记录，跨会话需要时在既有项目接续中保留引用，不建平行数据库。新项目可以选聊天/文档或 Review。已有 Review 链的项目继续使用该链，只有用户明确切换或记录服务故障并接受临时回退时才改用聊天。选用 Review 产品时，读取[工具接入](references/workflow-adapter.md)的 prepare/decide/note/return 约定；使用 Pipeline 剪辑工具本身不代表新项目必须注册 Review。
