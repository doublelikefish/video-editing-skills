# 修改后逐项核查

用于复合反馈、多条返工或反复退回。沿用原意见与现有记录；单条小改直接在原对话写明要求、结果、检查即可。这里规定核对动作，不增加一套登记系统。

## 从原要求建立核对项

在修改前，读原话、附件、后续补充及明确撤销，将每个可独立失败的要求列在同一反馈下。例如 F-03 的“稳定、稍微旋转放大”拆为稳定、水平校正、构图三项；不得在验收时按实际做了什么反向缩减要求。模糊幅度可由 Agent 判断，用户指定源文件/窗口/顺序则保留为约束。推荐候选和明确必用区分；不用候选写取舍，未满足必用要求不能靠说明变成完成。

另列本次修改会碰到的保留项。只列实际影响：换源可能影响输入转换、镜头参数和源声；改时长影响 VO/字幕/包装；改包装影响内外层合成。无需每次制造全片所有参数的检查表。

## 执行完成后，重新从要求检查

先打开有效原要求，再对照实际结果；不要让执行摘要成为唯一检查题目。每个条件回答：

- 实际采用哪个源、窗口/时间线区间、哪个最终文件或原生条目？位置变化用当前映射，不能照抄旧时码。
- 什么证据能证明这一条件？原生/解码测量证明技术事实，真实连续画面/声音证明对应效果；路径或一句“已处理”本身不证明满足。
- 结果是已核实、失败还是未查？失败/未查留下具体剩余项；模型建议与已确认观察分开。

同一段实际媒体可以覆盖多项，不必为每项重复导出或重复送图。每项必须说明该证据证明了什么。

| 要求 | 合适的核查 | 常见错误替代 |
| --- | --- | --- |
| 指定镜头/源窗口、先后顺序、切口覆盖 | 源身份及时间映射，实际片段中动作开始/落点，切口两侧的声画连续性 | 只找到同名源；把素材池存在当已采用；单帧代替动作 |
| 稳定、旋转、放大 | 各自处理读回与连续播放：抖动、水平、构图和边缘形变 | 把固定 Zoom 当稳定；做了三项之一就整条完成 |
| 换镜保留调色 | 新源的真实输入解释、转换是否已烘焙/重复，以及前后镜头匹配 | 盲拷旧机位 LUT；派生文件再次转色；新镜头漏转色 |
| 去旧标题、改多画面 | 内外嵌套层的实际可见贡献，以及最终合成的字、背景、遮罩、间距 | 只删主时间线一层；模板渲染正常就当整片正常 |
| 去重复 | 实际源窗口、动作阶段及整组顺序；必要时比较相邻组 | 同名文件直接判重复；文件名不同就判无重复 |
| 声音双侧可听/居中 | 有对白窗口内实际解码的逐声道能量、路由和播放；按需查 VO solo 与全混音 | channels=2；BGM 两侧有能量掩盖 VO 偏单侧；全片平均值 |
| 降噪、换音并保留电平/同步 | 处理前后的输入增益、轨道/总线、处理延迟、字头尾、VO 与 BGM 的相对关系及实际听感 | 有 WAV/峰值合格就通过；忘记原生前级增益；只听干声 |

## 以最终结果收口

局部样本通过后，对实际最终预览核对同一处及足够两侧上下文；检查对象必须能区分版本/文件修订。旧证据仅在相关源、时间、参数和合成依赖保持一致时复用。重剪/重混/换源后不能继承受影响项的旧通过结论；未受影响项可继续复用，避免每次全片重做。

覆盖本轮全部有效反馈及受影响的历史要求。先比较 ID 集合，找漏项，再比较各条条件。总数相等、回执齐全或全部 addressed 仍不证明语义满足。将已核实/部分/未查逐条返回，未完成可交付明确标记的候选，但不能说“全部改完”。用户接受独立，不由 Agent 填写。

## 工具边界

使用产品时，将上述条件写进它已有的决定与 checks 字段，用公开回调和并发修订保护；接口失败应修调用或保持缺口，不直接写反馈数据库、更改已删除意见或用脚本批量 resolved。无 Review 产品时，原聊天/文档中的同一组要求与结果即可。

工具能拒绝缺少已声明的检查、过期版本或 pending 冒充完成，不能自动知道 Agent 漏拆了一个要求，也不能证明一段声音自然。因此原要求核对与真实媒体核查都是制作负责人的工作；额外模型观察只提供证据，不自动授予通过。
