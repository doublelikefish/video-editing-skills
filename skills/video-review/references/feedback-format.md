# 反馈与回传格式

适用于直接聊天、文档和评审工具。格式帮助 Agent 恢复上下文与逐条处理，不要求用户填表或提供 JSON；用户只说“这里太吵”也可以，由 Agent 从当前预览和对话补齐能确定的信息，仅对会影响修改的歧义澄清。

## 一条反馈保留什么

- **标识与对象**：已有意见 ID；聊天无 ID 时用本轮稳定编号，如 F-01。关联实际文件/预览与版本，不能只写“最新版”。
- **位置或范围**：时间点/区间、镜头、台词、画面区域或全片；声明源时间还是成片时间。无法精确定位时保留具体线索，实际修改前再核对。
- **原要求**：保留用户原话及其补充/撤销；Agent 对问题、希望达到效果和保留范围的解释单列，不能伪装成用户要求。
- **当前处理**：本轮决定、实际结果和核查状态，跟随同一条反馈更新；旧版位置需要重新映射，不重新编号制造重复。
- **逐项条件**：复合要求在原条目内拆开，保留各自结果和未查项；例如稳定=已核实、旋转=未执行、构图=已核实，此条仍为部分完成。条件从原要求产生，不能从执行摘要倒推。

简单反馈在原对话用几行即可；多条反馈可用已有文档中的短表。截图、音视频、原生读回和工具日志按需引用，不再复制一整套凭证。

## Agent 如何返回

```text
F-01 · 原版 v03 / 成片 00:05–00:08
要求：用户原话；本轮已确认的补充/保留范围。
处理：实际改了什么；新版 v04 的文件/预览及对应位置。
核查：实际看/听的范围和结果；技术检查单列，不冒充听感。
复合要求按需补：每项条件 → 结果 → 对应证据/剩余；以及本次涉及的既有效果是否保留。
状态：已修改待复核 / 部分完成 / 待定位 / 待输入 / 无需修改（说明依据）。
剩余：具体未完成项；没有则省略。
```

“已修改待复核”表示制作和本轮核查完成，用户接受仍由明确确认或既有约定决定。“部分完成”保留未实施/未查范围；没有使用 Review 服务不是部分完成的理由。Agent 不能仅因发出回复就判定原问题解决。

## 切换载体

原对话或原文档可以完成整个循环，不需要随后补注册 Review。已在服务内的历史有效意见仍要回收；用户改用聊天时保留原 ID/链接和明确版本，聊天结果可以直接继续工作。只有明确要求服务同步时才跟踪同步状态，不将服务不可用变成禁止剪辑的条件。

已有 Review 链默认继续使用。Review 可选表示新项目可以不创建服务，不表示已有 v01/v02 链在 v03 时自动改成聊天直链。服务故障时临时聊天回传要记录原 Review 版本、原意见 ID、故障原因和待同步范围。

撤销、取代、证据补充、制作结果和用户接受分别记录；证据不能偷偷变成新的修改要求。跨会话在既有项目接续中保留当前版本、有效条目与未完成项的引用。先做真实修改和核查，再按选定载体回传。
